# SPECTRE-SENTINEL README ALIGNMENT PLAN

## Status

This artifact defines the required README-alignment plan for future Sentinel integration.

It is mandatory planning, not optional cleanup.

It does not itself change README.md.
It defines what README must be checked for and normalized before normative Sentinel wording is safe.

---

## 1. Purpose

This artifact defines the explicit README-alignment plan required before Sentinel future-integration wording can be treated as normative in the repo entry surface.

---

## 2. README Alignment Requirements

README must be checked and updated if needed so that:
- Sentinel is not implied as already-normalized runtime surface
- DTPE / IAL / SPECTRE responsibilities remain consistent
- future-integration wording is explicit
- BBIS is not accidentally collapsed into Sentinel
- any IAL naming mismatch is either resolved or explicitly bounded and explained

---

## 3. README Contradictions To Prevent

README must not imply:
- Sentinel is already a core runtime layer
- IAL positioning authorizes Sentinel runtime by implication
- Sentinel replaces SPECTRE
- Sentinel replaces DTPE evidence paths
- Sentinel itself solves BBIS
- future integration equals current normalized runtime authorization

---

## 4. README Normalization Targets

README should reflect:
- DTPE / IAL / SPECTRE as current public architecture triad
- Sentinel as future integration only
- IAL as canonical semantic artifact layer
- SPECTRE as execution / mutation-bound evaluator
- DTPE as receipt / ledger / offline verifier path
- BBIS as continuity requirement across the full mutation path

---

## 5. README Completion Rule

README alignment is complete only when:
- Sentinel future-only posture is explicit
- DTPE / IAL / SPECTRE boundaries are consistent
- BBIS is not collapsed into Sentinel
- no wording implies current runtime normalization by implication
- any naming mismatch is either resolved or explicitly bounded

---

## 6. Direct Rule

The direct README rule is:

README must not make Sentinel sound like a currently authorized public runtime layer. It must present Sentinel, if mentioned, only as a bounded future integration profile subordinate to DTPE / IAL / SPECTRE and still subject to docs alignment and BBIS completion constraints.
