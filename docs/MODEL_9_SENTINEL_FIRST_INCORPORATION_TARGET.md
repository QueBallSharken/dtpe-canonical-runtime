## 1. Purpose

This artifact defines the exact first incorporation target for Model 9 within SPECTRE-SENTINEL.

It is intentionally narrow.

Its purpose is to establish the first meaningful, bounded, replay-verifiable, non-advisory Model 9 incorporation target without overclaim.

It defines only:
- the exact bounded segment shape to target first
- the minimum state path required
- the minimum evidence chain required
- the exact permitted claim language
- the exact forbidden overclaim language
- the exact classification ceiling for the first target
- the PQC-ready posture that must remain active

## 2. Governing Target Rule

The first incorporation target must be narrow enough that SPECTRE-SENTINEL can prove one real bounded segment of active accompaniment with:
- one real refusal-capable covered boundary
- one governed transition identity
- one authority basis
- one invariant basis
- one timing-qualified refusal relation
- fail-closed downgrade behavior
- replay-sufficient evidence
- PQC-ready crypto posture preserved as an active requirement

Anything broader is out of scope for the first target.

## 4. Standing Architectural Requirement

PQC must be on and always at the ready.

For the first incorporation target, this means:
- the first target must not depend on a structurally legacy-only crypto posture
- where crypto posture is relevant to the bounded claim, it must be surfaced and handled
- unsupported or mismatched claim-relevant crypto posture must fail closed or downgrade
- the bounded first target must remain compatible with an active PQC-ready posture

This file does not require a full PQC migration program by itself.

It does require that the first target not be architected as if PQC can be deferred outside the core claim posture.

## 5. Exact First Target Shape

The first target is:

one explicitly declared accompanied segment containing one covered mutation-capable boundary at which SPECTRE-SENTINEL can prove:
- identity-bound continuity
- authority-bound continuity
- invariant-bound continuity
- mechanically effective refusal
- timely refusal
- replay-sufficient evidence
- fail-closed downgrade behavior
- claim-relevant crypto posture handling where applicable

This is the whole first target.

It is not:
- an end-to-end workflow target
- a multi-boundary target
- a multi-system target
- a downstream universal continuity target
- a truth claim about all possible mutation paths
- a full crypto-agility target

It is one bounded accompanied segment only.

## 6. First Target Segment Constraints

The first target segment must satisfy all of the following constraints.

### 6.1 Single Explicit Segment

The target must involve one segment only.

The segment must have:
- explicit start condition
- explicit end condition
- explicit scope statement
- explicit covered boundary
- explicit claimed irreversible primitive for that segment

No implied scope is allowed.

### 6.2 Single Covered Boundary

The first target must cover exactly one mutation-capable boundary.

Reason:
- this keeps the first claim narrow enough to verify
- this avoids premature claims about continuity across multiple boundaries
- this reduces ambiguity around alternate path and coverage loss

If more than one boundary is involved, that is a later target.

### 6.3 One Governed Transition Identity

The first target must track one governed transition identity only.

No split identity, merged identity, or transferred successor chain should be required in the first target.

Reason:
- successor continuity introduces additional proof burden
- the first target should prove direct continuity before transferred continuity

### 6.4 One Authority Basis and One Invariant Basis

The first target must use one authority basis and one invariant basis only.

No governed authority succession and no governed invariant succession should be required for the first target.

Reason:
- change-of-basis cases are harder and belong later
- first proof should be static and bounded

### 6.5 One Real Refusal Surface

The first target must include one refusal surface that is actually mechanically effective at the covered boundary.

This refusal must be able to stop or prevent the mutation within the segment scope.

It must not be merely:
- observational
- recommendatory
- alerting
- revocatory after mutation
- punitive after mutation

### 6.6 Timeliness Must Be Proven

The first target must prove that refusal was live in time relative to mutation completion at the covered boundary.

It is not enough to show that refusal existed in principle.

The first target must support the narrower stronger fact:
- refusal could act before mutation completion at the covered boundary

### 6.7 Explicit Claim Limitation

The first target must explicitly state what is not being claimed.

At minimum, it must explicitly not claim:
- end-to-end workflow accompaniment
- coverage of any second boundary
- coverage of external downstream mutation points
- alternate-path closure beyond the exact covered boundary scope unless explicitly implemented
- universal continuity
- full Model 9 implementation
- full BBIS closure
- broad crypto-agility completion
- full PQC migration completion

### 6.8 PQC-Ready Constraint

The first target must preserve an active PQC-ready posture.

That means:
- crypto posture must not be structurally hidden
- claim-relevant crypto posture must not be ignored
- claim-relevant crypto mismatch must not pass silently
- replay must be able to see crypto posture where the claim depends on it

## 7. Minimum State Path Required

The first target must support this exact minimum state path:

- Uninitialized
- Segment-Declared
- Identity-Bound
- Authority-Bound
- Coverage-Established
- Refusal-Live
- Actively-Accompanying
- Completed

Where crypto posture is claim-relevant, the target must also support:

- Crypto-Qualified

before Actively-Accompanying.

This is the required success path.

The first target must also support fail-closed exit from any stronger state when required.

---

## 8. Minimum Failure / Downgrade Paths Required

The first target must support at least these downgrade paths.

### 8.1 Refusal Failure Path

- Refusal-Live
- Advisory-Only
- Completed

or

- Actively-Accompanying
- Advisory-Only
- Completed

This is required to prove that refusal qualification matters.

### 8.2 Evidence Failure Path

- any stronger state
- Unverifiable
- Failed-Closed
- Completed

This is required to prove replay discipline.

### 8.3 Coverage Loss Path

- Coverage-Established or Actively-Accompanying
- Coverage-Lost
- Failed-Closed
- Completed

This is required to prove that stronger claims do not silently survive coverage failure.

### 8.4 Crypto Failure Path

Where crypto posture is claim-relevant:

- Crypto-Qualified or Actively-Accompanying
- Crypto-Failed
- Failed-Closed
- Completed

This is required to prove that crypto-dependent stronger claims fail closed when claim-relevant crypto posture is defeated.

## 9. Minimum Evidence Chain Required

The first target must surface evidence sufficient to reconstruct this chain:

1. segment declared
2. governed transition identity bound
3. authority basis bound
4. invariant basis bound
5. covered boundary established
6. claimed irreversible primitive established for the segment
7. refusal path bound to the covered boundary
8. refusal capability live
9. refusal timing qualified
10. active accompaniment state reached
11. downgrade recorded if failure occurs
12. final classification issued
13. evidence sufficiency result issued
14. claim-relevant crypto posture determined where applicable

If any of these links is absent, the first target is not complete.

## 10. Minimum Replay Result Required

Replay for the first target must be able to determine:
- what segment was claimed
- what scope was claimed
- what class was claimed
- what transition identity was governed
- what authority basis governed it
- what invariant basis governed it
- what boundary was covered
- what irreversible primitive was claimed
- whether refusal was live

- whether stronger classification survived replay
- whether downgrade was required
- what final class is supported
- whether claim-relevant crypto posture qualified where applicable

This is the minimum replay bar.

## 11. Exact Permitted Claim Language

The first target may use claim language no stronger than the following.

### 11.1 Strongest Permitted Claim

SPECTRE-SENTINEL supports bounded Model 9 active accompaniment for one explicitly declared segment with one covered mutation-capable boundary, where governed transition identity, authority basis, invariant basis, mechanically effective refusal, timing qualification, downgrade behavior, and evidence sufficiency are all supported for that exact segment scope, with claim-relevant crypto posture handled where applicable.

This is the strongest permitted first-target claim.

### 11.2 Narrower Permitted Claim

SPECTRE-SENTINEL supports replay-verifiable segment-bounded active accompaniment for a single covered boundary within a strictly limited claim scope.

This is also acceptable.

### 11.3 Permitted Downgraded Claim

If active qualification is not fully achieved, the allowed weaker claims are:

SPECTRE-SENTINEL supports governance-bound advisory accompaniment for a bounded segment.

or

SPECTRE-SENTINEL supports observed bounded segment tracking only.

Only the strongest justified one may be used.

## 13. Exact Classification Ceiling for the First Target

The first target's maximum honest classification is:

Segment-Accompanied

It may reach Actively Accompanied only for the exact bounded segment if the segment itself is the full claimed scope and all required evidence supports that exact scope.

But as a program-level public claim, the first target should still be framed as:

bounded segment accompaniment only

That is the safest and most accurate ceiling.

## 14. What Counts as First-Target Success

The first target counts as successful only if all of the following are true:
- one bounded segment is explicitly declared
- one covered mutation-capable boundary is explicitly identified
- one governed transition identity is bound
- one authority basis is bound
- one invariant basis is bound
- refusal is mechanically effective at that boundary
- refusal is timely at that boundary
- replay can validate the bounded claim
- downgrade occurs when stronger conditions fail
- final claim language stays within the bounded ceiling
- claim-relevant crypto posture is handled where applicable
- PQC-ready posture remains preserved as an active requirement

If any one of these is missing, first-target success is not established.

---

## 15. What Does Not Count as First-Target Success

The following do not count:
- merely spawning a monitoring process
- merely attaching a sidecar
- merely recording policy identity
- merely logging boundary events
- merely showing persistence of a process
- merely proving observation over time
- merely declaring a covered boundary without real refusal
- merely asserting replay compatibility without sufficient evidence
- merely demonstrating advisory accompaniment
- merely demonstrating a conceptual state model
- merely surfacing crypto posture without making it matter where the claim depends on it
- merely stating that PQC matters without preserving it in the bounded architecture posture

Those may be prerequisites or partial progress, but they are not first-target success.

## 16. Recommended First-Target Evaluation Question

The first target should be judged by this exact question:

For one explicitly bounded segment and one explicitly covered mutation-capable boundary, can SPECTRE-SENTINEL prove that the same governed transition remained identity-bound, authority-bound, invariant-bound, refusal-capable, timely-refusal-capable, downgrade-disciplined, replay-verifiable, and claim-relevant-crypto-qualified where applicable, for that exact scope only?

If the answer is yes, the first incorporation target is valid.

If the answer is no, it is not yet valid.
